## 0. 事前確認（ユーザー回答・実測結果）

### 0-1. 実装前に確認した仕様

| 論点 | 決定 |
| :--- | :--- |
| UI上の位置付け | CLI専用画面を分離せず、既存のLLMプロファイル種別として追加する。既存のプロファイル別OCR・翻訳・解説チップ、プロンプト、キャッシュ、ログをそのまま利用できるため。 |
| 導入と認証 | PATH自動検出、手動パス、モデル取得、案内を実装する。第三者CLIのインストールやOAuthログインは外部状態を大きく変更するため自動化しない。 |
| モデル | `model_name` はAPI／CLIで共用し、取得候補からの選択と自由入力を両立する。CLI新規プロファイルは各社の軽量モデルを既定にする。 |
| 実行権限 | リクエスト単位の一時ディレクトリを作業ディレクトリとし、各CLIで利用可能なread-only／ツール制限オプションを付ける。シェル文字列は組み立てず、実行ファイルと引数を分離して起動する。 |
| 失敗処理 | 120秒で子プロセスを終了し、stderr・終了コードをマスクしたエラーとして返す。別エンジンへの暗黙フォールバックは行わない。 |
| ログ | CLIが構造化出力でusageを返す場合だけtokens_in/outを保存する。取得不能時はNULLとする。 |
| アプリ一覧間の移動 | 選択行を元一覧から取り除き、反対側の末尾へ追加して即時保存する。既に移動先へ同名がある場合は重複追加せず、元一覧からだけ取り除く。 |
| BossGuard | 設定値として永続化し、アプリ自身を識別する表示名・開発者名だけを空白へ置き換える。対象アプリのタイトルやexe名、機能名、バージョン・更新日は維持する。 |
| クリップボード | HTML形式を優先してMarkdownへ変換し、HTMLが無くRTFがある場合も基本書式をMarkdownへ変換する。Unicodeプレーンテキストは空判定にのみtrimを使い、取得した文字列自体は変更しない。 |

### 0-2. 公式仕様とローカル実測

- Codex CLI: `codex exec` が非対話実行、`--image` が画像添付、`--output-last-message` が最終応答のファイル出力に対応。
- Claude Code: `claude -p` が非対話実行、`--output-format json` が構造化出力に対応。画像はプロンプト内でパスを指定して読ませられる。
- GitHub Copilot CLI: `copilot -p` がプログラム実行に対応し、`-s` で付加表示を抑制できる。画像対応モデルでは画像ファイルを添付できる。
- Gemini CLI: `gemini -p` が非対話実行、`--output-format json` が構造化出力に対応。組み込みread_fileは画像を扱える。
- Kimi Code CLI: `kimi -p` が非対話実行、`--output-format` が出力形式指定に対応。K3は画像入力に対応し、ReadMediaFileで画像を読める。
- ローカル環境ではClaude Code 2.1.197を検出。初回実装時はCodexを開発サンドボックスから起動できなかったが、導入完了後に通常ユーザー環境でCodex CLI 0.147.0とChatGPTログインを確認した。Copilot/Gemini/Kimiは未導入のため、全CLIのコマンド構築・解析は単体テストし、Codexのみ実アカウントprobeも実施した。

## 2. 要件別・実装方針

### 2-1. 定額プランを利用するLLM CLI実行機能

> 既存のLLM APIと同様に、Codex、Claude、GitHub Copilot、Gemini CLI、Kimi Code CLIを呼び出し、OCR・翻訳・解説を実行する。

| 項目 | 内容 |
| :--- | :--- |
| 実装箇所 | `src/config.rs`, `src/llm_cli.rs`（新規）, `src/llm_api.rs`, `src/settings.rs` |
| プロファイル | `ApiType`へCLI5種を追加し、`ApiProfile`へ実行ファイルパスを追加する。API URL／APIキーはCLI種別では使用しない。 |
| 実行方式 | `std::process::Command`へ引数を個別設定し、シェルを介さない。PNGがある場合だけ一時ファイル化し、CLI別の公式な非対話引数で呼ぶ。stdout/stderrをUTF-8として回収する。 |
| 安全性 | 一時ディレクトリをcwdにし、Codexはread-only sandbox、Claudeは読み取り系ツールだけ、他CLIも利用可能な承認／権限制限を適用する。一時ファイルは処理後に削除する。 |
| タイムアウト | 標準ライブラリで子プロセスを監視し、120秒経過時にkillして待機・回収する。 |
| 出力 | CLI別にJSON／JSONL／テキストから最終本文とusageを抽出し、既存の`LlmResponse`へ正規化する。 |
| キャッシュ | APIリクエストJSONの代わりに、CLI種別・モデル・プロンプト・画像内容を含む安定した疑似リクエストJSONを生成し、既存DBキャッシュキーを維持する。 |
| UI | 種別選択にCLI5種を追加。CLI時はAPIキー／最大Tokenを無効化し、実行ファイル欄・検出状態・モデル取得・案内を表示する。 |
| 既存機能との衝突 | APIプロファイルは従来の挙動を保持する。CLIプロファイルも`is_ready`／`is_external`を共通利用し、チップ列・同意・ログの分岐漏れを防ぐ。 |

### 2-2. 利用可能モデルの選択UI

> API／CLIで利用可能なモデルを取得して編集可能なプルダウンへ表示し、CLIの既定値を軽量モデルにする。

| 項目 | 内容 |
| :--- | :--- |
| モデル欄 | Win32の編集可能コンボボックスへ変更し、一覧選択と自由入力を両立する。 |
| API一覧 | OpenAI互換 `/models`、Gemini ListModels、Claude Models APIを種別ごとに呼び分ける。 |
| CLI一覧 | CLIが機械可読な一覧を提供する場合は実行結果を解析し、提供しない場合は公式のモデル候補を表示する。 |
| 軽量既定値 | Codex=`gpt-5.6-luna`、Claude=`haiku`、Copilot=`claude-haiku-4.5`、Gemini=`gemini-2.5-flash-lite`、Kimi=`k3-256k`。 |
| 無効化 | CLIではAPIキー／最大Token、APIではCLI専用項目など、種別上使用しない入力を無効表示する。 |
| 失敗時 | 一覧取得に失敗しても現在の自由入力値を消さず、エラーを状態欄へ表示する。 |

### 2-3. ホットキーと名称の追加修正

> Kimiの名称をKimi Code CLIへ統一し、範囲選択の多重起動とESC終了不良を直し、プレビューキーを既定で無効にする。

| 項目 | 内容 |
| :--- | :--- |
| Kimi名称 | 設定種別と既定プロファイル名を「Kimi Code CLI」へ統一し、旧既定名「Kimi K3」は設定読込時に移行する。 |
| 多重起動 | 範囲選択ウィンドウを単一管理し、起動済みなら新規作成しない。グローバルホットキーには`MOD_NOREPEAT`を付ける。 |
| ESC | 範囲選択中はフォーカス非依存のESCポーリングも行い、ピン留めオーバーレイは前面ウィンドウ条件を外して閉じる。 |
| プレビューキー | 選択肢に「なし」を追加してConfig既定値にし、仮想キー0ではポーリングしない。既存設定で明示済みのLCtrl等は維持する。 |

### 2-4. アプリ別リスト間の移動

> OCR優先アプリリストと実行しないアプリリストの間に、双方向の矢印付き移動ボタンを置く。

| 操作 | 選択行を反対側の末尾へ移し、保存・メイン設定再読込・起動中アプリ一覧更新を1操作で行う。 |
| 整合性 | 大文字小文字を無視した同名項目が移動先に存在する場合は重複を作らず、元側のみ削除する。 |

### 2-5. BossGuard

| 項目 | 内容 |

### 2-6. クリップボードのMarkdown取込

> リッチテキストをMarkdown形式へ変換して記録し、プレーンテキストでも原文の再現性を高める。

| 項目 | 内容 |

## 4. 実装で判明した追加対応

- npm等で導入されるCLIはWindows上で `.cmd` になる場合がある。OCR対象文字列やプロンプトを
  コマンド引数へ直接渡すと、バッチファイルを起動する層で引用符やメタ文字が再解釈される
  余地があるため、Codex/Claude/Gemini/Kimiはstdin、Copilotは一時`request.txt`から
  read-onlyで読み取る方式へ変更した。モデル名はCLI引数として必要なため、英数字と
  `- _ . : /` のみに制限する。
- `version-bump`スキルのBashスクリプトは、この実行環境でWSLの`CreateInstance/E_ACCESSDENIED`となり起動できなかった。スクリプトが対象とする`Cargo.toml`、`installer.iss`、`src/settings.rs`の3箇所を同じ値へ手動更新し、`cargo build`で`Cargo.lock`を同期した。
